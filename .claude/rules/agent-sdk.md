# 에이전트 SDK 불변식

이 패키지는 **사용자 앱 번들에 들어간다**. 다른 패키지와 판단 기준이 다르다.

- **의존성 0** (`@crosspane/protocol`은 타입 전용이라 런타임 코드가 없다).
  편의 라이브러리를 추가하지 말 것 — 번들 크기가 곧 채택 장벽이다
- **페이지 동작을 절대 바꾸지 않는다**:
  - 훅은 원본을 먼저 호출하고 그 결과를 그대로 반환한다 (console/fetch/XHR)
  - fetch 바디는 `response.clone()`으로만 읽는다 — 원본 스트림 소비 금지
  - 전송 실패·서버 부재가 페이지에 영향을 주면 안 된다 (조용한 재시도, 큐 상한)
- **`enabled: false`면 아무것도 설치하지 않는다** — 게이팅은 성능이 아니라
  신뢰의 문제다(스토어 빌드 심사). 훅 설치 후 무시하는 방식으로 바꾸지 말 것
- **중복 init 금지** — `initCrosspane`은 활성 에이전트가 있으면 그것을 그대로
  돌려준다. 이중 후킹은 이벤트 중복 + dispose가 한 겹만 복원하는 영구 오염을 낳는다
- **직렬화 핫패스는 측정 없이 손대지 말 것** (`src/serialize.ts` 상단 + `scripts/bench.mjs`).
  실측으로 결론 난 것들: 네이티브 `JSON.stringify`가 예산 안 값에서 가장 빠르다(손으로 쓴
  순회는 3배 느렸다) / 큰 배열은 `length`가 O(1)이라 앞쪽만 자르는 것이 250배까지 이득이다 /
  키 5만 개 객체는 어떤 구현으로도 ~7ms가 바닥이다(V8 키 열거)
- **텍스트 상한(`maxTextLength`)을 우회하지 말 것** — 거대 객체를 로그하는 페이지가
  링버퍼와 회선을 잠식한다. 자를 때는 잘렸음을 문자열에 남긴다(조용히 버리면 오도한다)
- **`dispose()`는 원본을 복원한다** — 훅 설치 함수는 항상 해제 함수를 반환할 것
- **캡처를 꺼내는 경로는 최신 API만으로 짜면 타깃 환경에서 전부 실패한다** (실측):
  QA 기기가 사내 빌드를 여는 `http://<사내 IP>`는 보안 컨텍스트가 아니라
  `navigator.clipboard`·`navigator.share`가 **정의조차 되지 않는다**. `execCommand('copy')`가
  폴백이 아니라 이 환경의 주 경로다 — deprecated를 이유로 지우지 말 것(`clipboard.ts`).
  다운로드(`a[download].click()`)도 앱이 구현하지 않은 웹뷰에서는 조용히 실패하고
  성공 여부를 알 방법이 없다. 새 내보내기 수단을 추가할 때는 비보안 컨텍스트에서
  실제로 되는지부터 확인할 것
- **성공/실패를 반드시 반환한다** — 조용히 실패하는 내보내기는 QA가 버그 대신 툴을
  의심하게 만든다. `copyCapture()`가 boolean을 돌려주는 이유다
- **링버퍼는 크래시 대비다**: 페이지가 죽으면 에이전트도 죽으므로, 이벤트는
  도착 즉시 버퍼에 들어가야 한다 (전송 성공 여부와 무관하게)
- **프라이버시 기본값**: 응답 바디는 옵트인(`captureBodies`)이다. 기본값을
  켜는 방향으로 바꾸지 말 것
- 테스트는 jsdom — `PromiseRejectionEvent` 등 없는 생성자가 있다.
  `new Event(...)`에 필드를 실어 대체한다
