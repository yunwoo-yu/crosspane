# MCP 서버 불변식 (`crosspane mcp`)

목적: 코딩 에이전트가 "결제 웹뷰에서 왜 실패했어?"를 **직접** 질의한다.
사람이 대시보드를 열어 읽고 다시 옮겨 적는 왕복을 없애는 것이 전부다.

## stdout은 JSON-RPC 전용 채널이다

- `crosspane mcp` 경로에서 **`console.log`를 절대 쓰지 말 것**. 한 줄이라도 섞이면
  클라이언트가 파싱 실패로 연결을 끊는다. 진단은 `debugLog`(stderr)로만
- `index.ts`의 `argv[0] === 'mcp'` 분기가 `--help`/`--version`보다 **먼저** 온다 —
  안내 출력이 프로토콜 스트림에 섞이지 않게 하는 유일한 지점
- 프레이밍은 줄바꿈 구분 JSON. `JSON.stringify`가 개행을 내보내지 않는다는 사실에
  의존하므로 직접 문자열을 조립하지 말 것

## 허브에는 대시보드 클라이언트로 붙는다

허브는 `/ws` 접속 시 hello + 히스토리를 전량 재생한다. MCP 서버가 그 클라이언트가
되면 조회 API도, 공유 상태도, 허브 수정도 필요 없다. **허브에 MCP용 엔드포인트를
추가하지 말 것** — 같은 데이터를 두 경로로 노출하면 둘이 갈라진다.
- `hello`는 세션 경계다. 재접속 시 스토어를 비우지 않으면 히스토리가 중복 누적된다
  (대시보드에서 실측된 버그와 같은 원인)
- 허브 부재는 정상 상태다 — 조용히 지수 백오프로 재시도하고, 툴이 연결 상태를 보고한다.
  기동 실패로 프로세스를 죽이지 말 것 (클라이언트가 서버를 먼저 띄운다)

## SDK를 넣지 않는다

`@modelcontextprotocol/sdk`는 4MB가 넘고, 우리가 쓰는 것은 툴 전용 서버의 5개
메서드뿐이다. `crosspane`은 npx로 받는 CLI라 설치 크기가 첫 실행 체감이 된다.
직접 구현이 오히려 순수 함수로 테스트된다 (`rpc.ts`는 스토어만 주면 검증 가능).

## LLM 소비자를 전제로 설계한다

- **출력은 JSON이 아니라 줄 단위 텍스트** — 같은 정보를 절반 이하 토큰으로 싣고,
  사람이 대화창에서 그대로 읽는다
- **세션 지시자는 관대하게** — id·정확한 라벨·라벨 부분일치·id 접두사를 모두 받고,
  세션이 하나면 생략을 허용한다. 여러 개일 때 조용히 아무거나 고르면 오답이 된다
- **실패에 후보를 실어 준다** — 세션을 못 찾으면 목록을 함께 돌려줘 다음 호출에서
  스스로 고치게 한다. 되묻게 만들면 왕복이 두 배가 된다
- **툴 실행 실패는 프로토콜 오류가 아니다** — `isError: true` 결과로 돌려줘야
  모델이 대화를 이어가며 복구한다 (MCP 규약)
- **자른 것은 밝힌다** — limit·링버퍼로 버린 이벤트 수를 출력에 남긴다.
  조용히 자르면 모델이 전량으로 오해하고 "에러 없음"이라 답한다

## 새 툴을 추가할 때

1. `tools.ts`의 `TOOL_DEFINITIONS`에 정의 (description에 **언제 부를지**를 쓸 것 —
   무엇을 하는지만 쓰면 호출률이 떨어진다)
2. `callTool` 스위치에 핸들러 추가. 세션이 필요하면 `withSession`으로 감쌀 것
3. `tests/mcp-tools.test.ts`에 케이스 추가 — 필터가 실제로 걸러내는지까지
